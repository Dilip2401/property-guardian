PROPERTY GUARDIAN V10 — OWNER INFORMATION REQUESTS + UX

1. Owner -> Admin notification routing
   - When an owner selects “Ask for more information”, a persistent notification is created for Admin only.
   - Guardians receive no notification from this workflow.
   - Admin header has a notification bell, unread count, notification panel, mark-read and mark-all-read interactions.
   - Clicking a notification opens the related issue case.

2. Rich issue case experience
   - Added full Issue Case modal with workflow steps, property/room context, visit details, observation, occurrence history, evidence, Admin review, Owner decision, Admin response and AI insight.
   - Added clearer action states and a “View full case” interaction.

3. Admin response workflow
   - Admin can open an owner information request and respond with a detailed note.
   - Responding marks the notification as read, records an Admin response and returns the issue to sent_to_owner/awaiting owner review.
   - No Guardian notification is generated by this response.

4. Admin operations usability
   - Added an “Attention required” section for outstanding owner information requests.
   - Explicitly explains that these requests are routed to Admin only.

5. Data/API improvements
   - Added /api/notifications and /api/notifications/read endpoints.
   - Added /api/admin/respond-more-info endpoint.
   - Added notification persistence/migration support.
   - Tightened owner property authorization on owner decisions.
   - Fixed report endpoint status filtering to use string status values safely.

6. Preserved V9 behavior
   - Login/logout, Property Passport, Guardian checklist/evidence, Admin inspection review, Issues & AI and History remain intact.
